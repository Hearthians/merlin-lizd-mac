# TmuxHub for macOS

TmuxHub 是一个原生 macOS SSH 终端管理器，支持 tmux 和 Herdr。它直接使用系统
OpenSSH、`~/.ssh/config`、SSH Agent 和目标主机上的终端服务，不依赖任何云平台 CLI，
也不集中保存各主机的私钥或平台 token。用户可以按主机选择是否把 SSH 密码安全保存到
macOS 钥匙串，作为密钥认证失败后的回退。

原 Merlin 平台版本完整保存在 `merlin` 分支；当前分支包含通用 SSH 终端
功能。

## 功能

- 把 `~/.ssh/config`（含递归 `Include`）作为可搜索主机库，而不是把每个目标都塞进侧边栏。
- 侧边栏只显示用户固定的主机和最近 7 天成功连通过的 6 个目标；手动添加会自动固定。
- 在 App 内添加 SSH 主机，填写地址、用户名、端口和可选私钥，自动保存连接配置。
- 裸 IPv4/IPv6 地址默认从主机库首页隐藏，但仍可搜索、手动添加和正常连接。
- 快捷连接优先回到已有标签；首次连接使用稳定的默认 tmux 会话名，主动新建才生成新会话。
- 浏览、创建、接入、重命名和批量终止本机或远端 tmux 会话。
- 在主机详情或本机页面一键应用 tmux 快捷配置，自动备份并保留其他设置。
- 浏览本机或远端 Herdr 工作区、Agent 和终端，直接打开所选终端。
- 远程终端由 tmux 或 Herdr 托管；关闭 App 标签只断开 SSH，远端任务继续运行。
- SSH 断开后可以原地重连同一个 tmux 会话或 Herdr 终端。
- 使用 App 自己的 OpenSSH ControlMaster 复用连接，加快刷新与 tmux 操作。
- 点击 SSH 终端里的远端 `localhost:<端口>` 网页链接时，自动建立本机端口转发并打开浏览器。
- 每个主机可选密码回退；默认仍优先使用 SSH config、私钥和 SSH Agent。
- 查看主机和后台连接不会自动弹出钥匙串授权；需要时在主机详情手动授权使用已存密码。
- 可以把同一会话安全地交给 macOS Terminal.app 打开。
- 保存本地标签和 tmux 身份，tmux 改名后仍能正确关联会话。
- 拖入文件、粘贴 Finder 文件或 ⌘V 截图，传输完成后把可访问路径插入当前终端。
- 附件栏提供缩略图、状态、取消、重试、复制路径和手动插入；始终不自动按 Enter。

Codex completion/approval notifications, shared read status across Macs,
and reconnect behavior are documented in [Codex notifications](Docs/codex-notifications.md).

## 添加 SSH 主机

点击主机库的「添加 SSH 主机」、侧边栏的 **+**，或按 **⌘⇧N** 打开添加窗口。

- 「新建主机配置」填写主机别名和地址，支持域名、IPv4 和 IPv6。用户名可留空，端口默认 22；
  私钥可填写路径或选择文件，留空时使用已有密钥和 SSH Agent，也可在连接时输入密码。
- 保存到 `~/.ssh/config`，终端、会话列表和文件传输共用这些参数。保存前自动备份已有配置，
  保留原有内容；重复别名会提示修改，不覆盖已有主机。
- 「已有 SSH 目标」继续支持直接添加 alias、hostname 或 `user@host`，无需创建配置条目。
- 添加成功后自动固定并打开主机详情，点击「连接或继续」开始连接。

## 主机互联

侧边栏「主机互联」按物理主机归并校园网、ZeroTier 等入口；Windows、WSL 等运行环境可独立配置。

- 「成员」勾选需要互联的主机并应用。导入的 SSH 主机默认仅登记，在线状态仍可查看。
- 「接入」完成首次登录与指纹确认、工具检查和双向免密码 SSH 配置；离线任务保留并重试。
- 「矩阵」按来源 → 目标展示互通状态，点击格子查看具体地址路径。默认校园网优先，网络连接失败后尝试 ZeroTier；认证和指纹异常需要处理。
- SSH 测速传输 32 MiB，独立带宽测速使用 iperf3。两种结果分开保存，均显示 Mbps、测量时间及当时的来源/目标地址。
- 取消成员只撤销 TmuxHub 管理的互联授权；保留原有 SSH 配置、管理连接及历史记录。

首次接入可能需要在 Terminal 中输入密码或管理员授权。独立带宽测试要求两端安装 iperf3、测试端口可达；ZeroTier 加入后仍需网络管理员授权。向导会检查真实状态。作为测速来源的地址必须是该运行环境可绑定的网卡 IP；域名和公网映射地址可以作为目标入口。

管理连接使用本机 `~/.ssh/tmuxhub_management_ed25519`；每个运行环境使用自己的 `~/.ssh/tmuxhub_mesh_ed25519`。只交换公钥和经认证取得的主机指纹，私钥留在原主机。Windows 多个管理员账户默认共用系统授权文件；需要账户隔离时应使用普通用户或先配置独立授权路径。

## 主机与平台属性

右键点击侧边栏中的 SSH 主机或计算平台，选择「属性」。主机库卡片也有同一入口。

- SSH 主机属性显示当前实际使用的地址、用户名、端口、密钥和跳板设置，可直接修改地址、
  用户名和端口。保存前自动备份配置，保留其他选项；高级密钥和代理设置可打开 SSH 配置修改。
- 计算平台属性可修改显示名称、登录目标、集群用户名和默认资源配置。点击「保存」只保存设置，
  不启动任务；仍有活动或待确认的任务时，保留现有平台身份限制。
- 修改 SSH 设置不会打断已建立的连接。重启 TmuxHub 后，所有连接都会使用新设置。

## 钥匙串授权

主机详情只查询是否有已存密码，不读取密码内容。后台连接只使用已获许可的密码；若 macOS
需要新的访问许可，可在主机详情的「密码回退」中点击「授权使用已存密码」。系统弹窗要求
输入的是 Mac 登录钥匙串密码。保存、更新和移除密码也是主动操作，可能需要系统授权。

成功授权的密码只在当前 App 进程的内存中复用；更新或移除密码会同步更新这份缓存。
取消授权会保留原密码，后台不会再次弹窗；可以稍后手动重试。

目前本地构建使用 ad-hoc 签名，不同版本的程序身份可能改变，因此更新后可能需要重新
点击授权。「始终允许」针对当前受信任的程序身份，不能保证跨 ad-hoc 构建沿用。
若要让系统在升级后稳定识别同一程序，分发流程应使用固定的代码签名身份。

## 一键配置 tmux

选择目标主机，在「tmux 快捷配置」卡片点击「一键配置 tmux」。本机页面也有同一入口。
目标主机需已安装 tmux；远程操作复用 App 的 SSH 连接和认证设置。

- 前缀改为 Ctrl+A，连按两次向终端发送 Ctrl+A；启用鼠标选择、切换和滚动。
- 状态栏黑底白字，普通面板边框绿色、活动边框红色。
- 新窗口和面板从 1 编号，终端类型为 `screen-256color`。
- 在目标用户的 `~/.tmux.conf` 中添加或更新独立配置段；若已有 XDG 配置且没有
  `~/.tmux.conf`，则更新现有 XDG 文件。保留其他配置和符号链接。
- 修改前在原文件旁保存 `.tmuxhub-backup.<随机后缀>` 备份，完成后显示完整路径。
  重复应用相同配置不会增加配置段或生成新备份。
- 正在运行的默认 tmux 服务会立即加载这组设置，现有任务继续运行；编号和终端类型
  用于新建窗口、面板或会话。尚未运行 tmux 时，下次启动自动生效。
- 若配置已保存但当前服务加载失败，界面会单独提示，可再次点击重试。

如需恢复，可用显示的备份文件替换对应配置文件，并在方便时重启 tmux。
该入口管理默认 tmux 服务；通过自定义 socket 或 `-f` 启动的独立服务需自行加载配置。

### Vim 粘贴缩进修复

若在 tmux 内向 Vim 粘贴多行代码后缩进不断增加，在目标主机的同一卡片点击
「修复 Vim 粘贴」。某些 Vim / terminfo 组合没有为 `screen` / `tmux` 终端启用
bracketed paste；即使 TmuxHub 正确发送粘贴标记，tmux 也会移除未被 Vim 请求的标记，
导致 Vim 把每一行当成键盘输入并再次缩进。只修改 tmux 的终端类型不能可靠解决。

此操作仅在目标用户的 `~/.vim/plugin/tmuxhub-paste.vim` 中保存兼容设置，不修改
`.vimrc` 或关闭日常自动缩进；已有同名文件会先备份，相同内容重复应用不会产生新备份。
保存当前文件后重新打开 Vim 即可生效，无需重启 tmux 或结束其中的任务。
配置仅作用于终端类型以 `screen` / `tmux` 开头且支持相应选项的 Vim，跳过 GUI Vim
和 Neovim；以 `--noplugin` / `-u NONE` 等方式禁用插件启动时不会自动加载。
界面显示设置文件及备份路径，移除该插件文件即可撤销新安装的设置。

## 终端快捷键

终端支持 Ctrl+/、Ctrl+数字/符号、Ctrl+Option 组合，以及带 Shift、Control、Option
的方向键和功能键。应用启用增强键盘协议后，也会保留 Shift 组合的原始按键身份。

- 传统终端编码下，Ctrl+/ 与 Ctrl+_ 发送相同输入，远端程序无法把它们绑定为不同操作。
- 使用上面的一键 tmux 配置时，Ctrl+A 是 tmux 前缀；连按两次才能传给终端内的程序。
- macOS 已分配的全局快捷键可能在到达 Hub 前被系统截获，例如输入法切换或桌面切换。
  可在「系统设置 → 键盘 → 键盘快捷键」检查；Hub 不会自动修改这些设置。
- Option+左右方向键保留按单词移动，Shift+PageUp/PageDown 保留终端回滚。

## HKUST HPC2 / HPC3 / HPC4 / Slurm

侧边栏分别提供「HKUST HPC2」「HKUST HPC3」「HKUST HPC4」Slurm 任务页面，用于查看当前及
历史任务，以及启动、连接和取消 TmuxHub 创建的交互环境。默认 SSH 目标分别为 `hpc2`、`hpc3`、
`hpc4`，集群用户为 `zli760`；连接、启动参数、任务记录和费率按平台独立保存，切换平台不会混用。
SSH 目标及用户可在平台属性或启动表单中修改。首次启动默认使用 `debug` 分区、30 分钟；
HPC2 / HPC3 默认请求 1 个 GPU，HPC4 默认仅请求 CPU。

交互环境采用「登录节点 tmux + `srun --pty`」结构：TmuxHub 先通过对应平台的 SSH 目标进入登录节点，
在独立 tmux 会话中执行 `srun`，再由 Slurm 分配临时计算节点。计算节点名称和 IP 只作为
任务状态展示，不会加入 SSH 主机库。

- 平台页显示当前用户的排队中和运行中任务；历史页从对应集群的 Slurm accounting 读取最近
  7 / 30 / 90 天任务，也包含从其他终端提交的任务。由其他方式提交的任务只读显示。
- 「队列资源」读取当前集群的实时分区和节点，默认展示该平台常用队列及当前配置分区，可展开全部队列。
  HPC2 包含 A800 / A40，HPC3 包含 ACD；HPC4 包含 `a128m512u` / `a128m512ue` / `emergency`
  CPU 队列以及 `a320m2tn910cu` / `a320m2tn910cue` / `emergency_a320m2tn910c` NPU 队列。
  分区和资源数量以实时 Slurm 返回为准，不能用较早文档中的 HPC4 `hpc` 分区替代。
  GPU / NPU 分别显示总量、已分配和未分配数量；仅 GPU 队列显示按单节点统计的 4 / 8 卡空位，
  队列监控中的 NPU 数量保留资源单位，费用估计另行折算为物理卡数。共享节点的队列不可相加。
  空位不代表可立即启动，仍受 CPU、内存、优先级、配额和节点状态限制。
- 当前任务显示 GPU / NPU / CPU / 内存分配；支持的 GPU 运行任务可通过已有作业内的短暂监控 step
  读取各节点所分配 GPU 的利用率、显存和功率，最多同时采样 3 个任务，不申请新的作业资源。
  HPC4 任务资源中的 NPU 数量按 Slurm 报告的资源单位显示，费用明细同时显示折算后的物理卡数；NPU 实时利用率、显存和功率暂未接入。
  CPU 按当前活动 step 的累计 CPU 时间 / 作业运行时长 / 已分配核数估算，已结束 step 可能未计入；
  内存为 Slurm 记录的单个 task 的 RSS 峰值（可能包含子进程）。
  不支持、超时或无权限的指标显示「—」及原因；队列读取失败时保留旧数据并标明采样时间。
  页面打开时队列约每 60 秒、任务约每 30 秒刷新，也可手动刷新。
- 「启动交互环境」可设置分区、CPU、内存、GPU、时限、工作目录和环境初始化命令。
- TmuxHub 创建的任务可以直接连接到对应 tmux，也可以明确选择「取消任务并释放资源」。
- 关闭终端标签、关闭 App 或 SSH 断开只会分离终端，不会取消 Slurm 任务。
- 取消操作只对本 App 保存了完整启动身份的任务开放，避免误操作同一账号下的其他作业。
- 使用前应确保相应的 `ssh hpc2`、`ssh hpc3` 或 `ssh hpc4` 已能通过 SSH key / SSH Agent
  非交互登录；平台后台刷新不依赖终端中的密码输入。
- 当前任务及历史任务可显示计算费用估计，按已分配资源和实际运行时间计算，费率可按平台修改。
  HPC3 采用[官方公开参考价](https://docs.hpc.hkust-gz.edu.cn/docs/charges/prices-phaseIII/)：
  2025 年 9 月 1 日启用的 ACD 低 / 中 / 高档分别为 2.40 / 3.75 / 6.00 元每 GPU 小时，
  不附加 HPC2 的 CPU 费用；队列档位参考[HPC3 队列说明](https://docs.hpc.hkust-gz.edu.cn/docs/hpc3/slurm/queue/)。
  参考价可调整，实际结算以平台账单为准；MIG 等不能确认计价单位的资源不估算。
  HPC4 采用[价格速查](https://mcnj47nsbq2m.feishu.cn/wiki/Rhr9wjK8FiK15DkjA33cruc5nWg)（2026-10-21 核对）：
  ARM CPU 低 / 中 / 高档为 0.01 / 0.02 / 0.03 元每核小时，910C NPU 为 0.84 / 1.30 / 2.10 元每物理卡小时。
  已知 CPU 队列 `a128m512u` / `a128m512ue` / `emergency` 与 NPU 队列
  `a320m2tn910cu` / `a320m2tn910cue` / `emergency_a320m2tn910c`，
  按实测调度优先级 100 / 200 / 300 推定低 / 中 / 高计价档位；未知队列和 debug 不推定免费。
  NPU 分配数按默认 2 个资源单位折算 1 张 910C 卡，16 单位按 8 卡计价；
  依据为[官方每节点 8 卡规格](https://itdid.hkust-gz.edu.cn/cn/detail-968)、实际节点 `gres/npu:16`
  及[官方资源单位说明](https://docs.hpc.hkust-gz.edu.cn/docs/hpc4/domestic/quickstart-submit-ai-job/)。
  「计费标准」可查看和修改三档单价及 NPU 折算比例；旧版未配置的 HPC4 零占位费率自动迁移，已保存的自定义费率保留。
  NPU 任务暂按 NPU 卡时费另加已分配 ARM CPU 核时费估算；价目未说明 NPU 费用是否包含 CPU，页面明确标注这一假设，实际结算以账单为准。
  仅估算 Slurm 计算费用，不包含存储、包机租赁或 AIStudio 容器费用。

当前平台页可创建、连接和取消 TmuxHub 交互任务，并只读监控其他方式提交的普通任务。
GPU 实时采样暂不覆盖数组或异构任务。容器开发中心、镜像管理和 `sbatch` 提交尚未纳入。
HPC4 AIStudio 的 NPU 容器与 Slurm 作业是不同入口，参见[官方容器开发说明](https://docs.hpc.hkust-gz.edu.cn/docs/hpc4/domestic/quickstart-submit-ai-job/)；
其中 NPU 芯片数量和物理卡数量并不相同；资源监控保持集群原始计数，费用估计使用可配置的卡数折算比例。

## Herdr 工作区

在侧边栏主机行点击 Herdr 图标，或在主机详情的「Herdr 工作区」中点击「浏览工作区」，即可按
会话、工作区浏览现有终端。点击 Agent 或终端会直接打开对应的终端标签；已有标签
会被选中。列表在打开时读取最新状态，也可手动刷新。

- 目标主机需要已安装并运行支持 `api snapshot` 和 `terminal attach` 的 Herdr；
  已使用 Herdr 0.9.0 验证。本机和远程连接均可使用。
- TmuxHub 使用 Herdr 官方直接连接命令，不需要再套一层 tmux。
- 每个标签保存服务器会话名和稳定的 terminal ID。切换 Herdr 焦点或移动 pane
  不会把附件传给另一个 Agent；原终端不存在时需要重新选择。
- Herdr 未提供工作目录时仍可打开终端，但附件操作会提示目录不可用；未提供
  Agent 会话标识时，上传结果会保留为「就绪」，由你点击插入。
- 关闭标签只断开连接。也可按 Ctrl+B、再按 q 断开；输入 Ctrl+B 本身需连按两次。
- Herdr 同一终端仅允许一个直接控制客户端。如果已有客户端占用，连接会显示错误；
  请先断开原客户端，再重连。TmuxHub 不自动接管控制权。
- 本版只接入现有工作区和终端；创建、停止工作区仍在 Herdr 中操作。

参考：[Herdr 直接终端连接](https://herdr.dev/docs/cli-reference/#direct-terminal-attach)。

## 给 agent CLI 添加附件

把一个或多个文件拖到终端，或在截图后按 ⌘V。普通文字仍按原样粘贴；也可以
使用终端底部的「添加文件」和「粘贴截图」按钮。

- 远程会话：通过独立 SFTP 通道复用已认证的 SSH ControlMaster，上传到当前
  tmux pane 或所选 Herdr 终端工作目录的 `.tmuxhub/attachments/<唯一 ID>/`。服务器须开启 SFTP。
- 本机文件：直接引用原路径；剪贴板截图转为 PNG 并保存到上述附件目录。
- 目录按钮可为会话指定一个已存在的绝对路径，作为 `.tmuxhub/attachments` 的父目录。
- 文件完整上传后才插入路径。如果期间输入文字、切换标签、离开终端焦点，或检测到
  pane、前台程序、工作目录改变，附件会保留为「就绪」，由你点击插入。
- 支持每批 32 个普通文件，单个最大 100 MiB。不接收文件夹、软件包、符号链接或
  带控制字符的路径；请先自行打包。最多保留 100 条附件记录。
- 附件队列在当前 App 运行期间跨重连保留；关闭标签或退出 App 会取消传输。
  移除记录不会删除已保存或上传的附件。取消或失败可能在唯一目录中留下未完成文件。
  本机剪贴板暂存会在移除记录或关闭标签时清理；异常退出后的缓存可能保留。

这是通用的**文件传输 + 路径粘贴**，不是某个 agent 的专有图片协议。是否能把路径
识别为原生图片附件取决于 CLI；也可告诉 agent「读取这张图片」。若 agent 运行在
容器或权限受限的工作区中，请把附件目录设为它能访问的挂载路径。
附件目录不会自动加入 `.gitignore`；可按需忽略 `.tmuxhub/attachments/`。

## 在本机 VS Code 打开远端目录

默认启用：每次 SSH 连接会自动检查并安装或更新远端 `code` 联动，在 tmux 启动前完成。
远端需要 Python 3，本机需要 Visual Studio Code 和 Remote - SSH 扩展。
新 Bash/Zsh（含 Bash 登录 shell）直接可用；更新前已运行的 shell 请执行一次：

```sh
source ~/.local/share/tmuxhub/remote-editor/shell.sh
```

自动配置失败不会阻止终端连接，可在 SSH 主机详情的「本机 VS Code」中点击「修复 code 配置」重试。
重复连接不重复追加配置或生成备份；多设备同时连接时，安装过程会串行完成。

之后可在远端终端执行 `code .`、`code /path/to/project` 或 `code path/to/file.py`。
相对路径按远端当前目录解析，文件保留在服务器；文件夹名里的点、空格和中文会保留。
已有名为 `code` 的别名/函数不会被覆盖，此时可用 `tmuxhub-code .`。
在普通 SSH、非 TmuxHub tmux 客户端或 VS Code 集成终端中，仍交给原来的 `code` 命令。
本功能接受单个文件/目录路径，暂不代理 `--wait`、扩展管理等其他 VS Code CLI 参数。

只有一个符合条件的 TmuxHub 客户端时自动打开；多个设备同时连接该会话时，终端会让你
按设备名称选择目标，不会同时在其他设备打开。关闭或断开的客户端不会接收请求。
HPC2/3/4 登录节点会固定到当前实际节点，保留原 SSH 身份、跳板和主机密钥校验；
所需专用条目保存在 `~/.ssh/tmuxhub-code/`，并加入一个受限的 SSH Include。
计算节点上的嵌套 SSH 尚不支持，需返回登录节点或使用直接配置的 SSH 主机。

## 打开终端链接

SSH 终端中的 `http://localhost:<端口>/...`、`127.0.0.1`、`0.0.0.0` 和 `[::1]`
链接会在点击时通过该标签对应的 SSH 连接建立本地转发，再用系统浏览器打开实际的本机地址。
路径、查询参数和片段会保留；首次连接时若同号本地端口已被占用，TmuxHub 会选择其他空闲端口。
转发只监听本机 `127.0.0.1`，同一远端服务在标签间复用，关闭终端标签不会停止转发。
App 运行期间每 25 秒检查连接，Mac 唤醒或下次启动时恢复已启用的转发，并保持原来的本机端口；
若该端口被其他程序占用，会显示冲突而不会改成另一个地址。App 退出时清理实际连接。

侧栏「端口转发」保存点击过的远端网页，可直接重新打开、重连、复制本机地址、停止或移除。
完整链接保存在本机，页面隐藏查询参数和片段。停止会停用同一远端服务的所有链接；
移除只删除所选链接，其他链接仍可保留转发。远端网页服务本身也需要保持运行。
普通公网 URL 和本机终端中的 URL 仍直接打开。

转发目标是该标签配置的 SSH 主机本身。若终端随后又进入 Slurm 计算节点、容器或第二层 SSH，
其中仅在该嵌套环境 `localhost` 上监听的服务无法由外层连接直接访问；需要让服务对 SSH 主机可达，
或直接连接到实际运行服务的主机。

形如
`temp_output/r256/model/38.ply`、`./result.png` 或绝对路径的文件链接，**普通左键点击**会在
SFTP Downloader 中打开对应的 SSH 主机与位置：目录直接进入，文件打开所在目录并选中，
不会自动下载或预览。本机标签中的路径使用系统默认应用打开。拖动仍用于选择文字，
⌘+左键和普通右键不会触发文件操作。

没有扩展名的目录路径也可直接识别，例如 `temp_output/hssd_thick_comparison_8`、
`./results` 或 `/home/tiger/results`；括号和彩色输出不影响点击，终端自动换行时仍识别完整路径。

此联动需要安装支持 `sftp-downloader://open` 的新版 SFTP Downloader；更新两个 App 后
重新启动即可使用。主机沿用当前标签的 SSH 目标，相对路径按点击时的终端工作目录解析。
若应用未安装、文件不存在或位置不唯一，会显示具体错误。

**⌘ Command + 右键点击**继续使用下述下载并打开功能。

有选中文字时，**⌘+右键优先使用选中的内容作为文件路径**，不要求鼠标下方恰好是链接；
只有没有选区时才自动匹配点击位置。可以手动选中未识别的文件名、包含空格的路径，或跨行
显示的完整路径。跨行选区按一个路径处理，去掉换行及各行两端的排版空白，保留行内空格；
请一次只选一个文件。选区无效时不会改为下载鼠标下的其他文件。按下后改变选区、松开 ⌘
或拖动鼠标都会取消本次操作。

`ls` 彩色、多列输出中的带扩展名裸文件名（如 `rec_helmet.ply`、`rec_helmet.glb`、
`ovoxel_helmet_visualization.png`、`ovoxel_helmet.vxz`、`render_ovox.log`）同样支持，
按点击时终端的当前工作目录定位文件，不限制为特定扩展名：

- 远程 SSH/tmux 标签会先按点击瞬间的 pane 工作目录解析相对路径。若 agent 管理器
  的工作区与 pane 目录不同，TmuxHub 会在主目录下常见的一、二级工作区布局中按完整
  相对路径查找，并且只接受唯一结果。随后弹出 macOS 保存面板选择本地位置；面板默认
  打开 `~/Downloads/_tmuxhub_download/`，并通过现有 SSH ControlMaster 的独立 SFTP
  通道下载。
- 本机标签中的文件路径直接使用默认 App 打开。
- Herdr 标签始终按所选终端的实际工作目录解析文件；不存在时直接提示失败，
  不会搜索其他工作区代替。
- 下载先写入所选目录中的唯一临时文件，成功后再替换最终文件；取消、失败或关闭标签
  会清理临时文件。选择已有文件时，macOS 保存面板会先要求确认覆盖。下载完成后
  TmuxHub 会立即用系统默认应用打开文件。

## 要求

- macOS 14 或更新版本
- Apple Command Line Tools，Swift 6
- 本机 `/usr/bin/ssh`
- 目标主机已安装所需后端：`tmux` 或 Herdr
- 推荐配置 SSH Agent；也可以在主机详情中保存密码，以便会话列表后台刷新

示例 SSH 配置：

```sshconfig
Host prod
    HostName 203.0.113.10
    User deploy
    IdentityFile ~/.ssh/id_ed25519

Include ~/.ssh/conf.d/*.conf
```

通配符 `Host *` 仍会作为 OpenSSH 规则生效，但不会作为可连接主机显示在侧边栏。
建议把稳定、易读的名称写在 `Host`，把可能变化的 IP、端口和跳板规则写在该条目的
`HostName`、`Port` 和 `ProxyJump` 中。`Host prod 203.0.113.10` 会被 OpenSSH 视为两个
可连接名称；若只想在 TmuxHub 中看到 `prod`，请只写 `Host prod`。

```sh
./scripts/test.sh
./scripts/test-attachments-ui.sh
./scripts/test-display-ui.sh
./scripts/test-links-ui.sh
./scripts/test-paste-ui.sh
./scripts/test-keyboard-ui.sh

```

默认测试包含本地 fake process、临时文件和本机 SFTP 协议往返，不连接真实 SSH
主机。AppKit smoke test 使用私有剪贴板，不会替换系统剪贴板。
显示测试会在已连接的 Retina / 普通显示器之间移动独立测试窗口，检查文字单元格、
分隔线、光标和终端网格是否同步；只有一种缩放比例时会跳过。

完成认证配置后，可对指定主机执行一个会自动清理的真实 tmux 生命周期测试：

```sh
./scripts/live-ssh-test.sh user@example.com
```

脚本使用唯一会话名验证创建、结构化发现、重命名和终止，并在异常退出时尝试清理。

附件真实联调（仅对你授权的主机运行；创建并清理唯一的临时目录和 tmux 会话）：

```sh
TMUXHUB_LIVE_ATTACHMENT_HOST=user@example.com ./scripts/test.sh
```

Herdr 真实联调使用独立的临时命名会话及目录，并在结束时清理：

```sh
TMUXHUB_LIVE_HERDR_HOST=user@example.com ./scripts/test.sh
```

## 安全边界

- 所有进程都以 executable + argv 启动；tmux 配置使用固定脚本，路径以参数传入，
  远程执行时对整个脚本做 shell 引用。
- SSH 目标拒绝空白、控制字符、shell 元字符和前导 `-`，避免 option 注入。
- tmux 会话名限制为 1–64 个安全字符。
- 未配置密码时，后台 SSH 查询使用 `BatchMode=yes` 和超时。
- 配置密码后，OpenSSH 仍先尝试公钥，再通过随 App 签名的 AskPass helper
  获取本次连接所需密码；密码不进入 argv、日志或 SSH 配置。
- 密码只作为对应 SSH 目标的 macOS 钥匙串项目持久化，可随时在主机详情移除。
- Control socket 位于当前用户专属的 `/tmp/tmuxhub-<uid>`，退出时清理。
- 只有用户明确选择“终止 tmux”时才会执行 `kill-session`。

SwiftTerm 1.14.0 vendored 在 `Vendor/SwiftTerm`，其中保留了让 Metal shader
进入标准 app resource 路径的小型打包补丁。
